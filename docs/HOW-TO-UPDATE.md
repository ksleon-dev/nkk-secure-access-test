# How to Release a New Version

Complete checklist for releasing a new version of NKK Secure Access.
Every step matters. Skip nothing.

> **Wichtig (Stand 0.3.0):** Der Auto-Updater-Endpoint in `src-tauri/tauri.conf.json`
> (`plugins.updater.endpoints`) zeigt noch auf ein privates Test-Repo. Bevor die
> Auto-Updates produktiv laufen, MUSS dieser Endpoint auf den finalen, oeffentlich
> erreichbaren Release-Host gesetzt werden (das Repo, von dem `latest.json` geladen
> wird). Die CI baut `latest.json` bereits repo-relativ (`github.repository`), das
> ist also nur diese eine Zeile in der Config. Ohne erreichbaren Endpoint sehen
> installierte Clients nie ein Update.

## 1. Bump Version Numbers

Seit 0.3.0 erzwingt die CI (Schritt "Verify version consistency"), dass diese
drei Versionen identisch sind, sonst bricht der Build ab. `branding.json`
`product.version` wird zur Laufzeit ohnehin aus der kompilierten Binary
ueberschrieben (Single Source of Truth = `Cargo.toml`), sollte aber zur Klarheit
mitgepflegt werden.

| File | Field | Example |
|------|-------|---------|
| `src-tauri/Cargo.toml` | `version = "X.Y.Z"` | **Master**, Line 3 |
| `src-tauri/tauri.conf.json` | `"version": "X.Y.Z"` | muss matchen |
| `package.json` | `"version": "X.Y.Z"` | muss matchen |
| `src-tauri/resources/branding.json` | `"version": "X.Y.Z"` | informativ (auto-override) |
| `docs/anleitung.html` | `Version X.Y.Z` | Inside `.version` div, around line 287 |

Ausserdem muss ein `CHANGELOG.md`-Eintrag `## [X.Y.Z]` existieren, sonst bricht
der Tag-Build ab.

## 2. Update News / Changelog

### In-App News (hardcoded fallback)
File: `src/screens/NewsScreen.tsx`
- Add a new entry at the TOP of the `FALLBACK_NEWS` array
- Fields: `id`, `date`, `type` ("update"), `version`, `title`, `body`
- Keep max 4-5 entries, remove oldest if needed

### Remote News (API)
Endpoint: `https://api.secure.nkk-hb.de/api/news`
Server: `192.168.0.50` (Debian 12 VM), path: `/opt/nkk-api/`
- Update the news JSON served by the Flask API
- Remote news overrides the hardcoded fallback when reachable

### HTML Anleitung
File: `docs/anleitung.html`
- Update version number (see step 1)
- Add new features/changes if relevant
- All images are base64 embedded (self-contained file)
- Send updated HTML to users or host it

## 3. Build

### macOS (local on Mac)
```bash
cd /Users/work/KronSolutions/KronSolutions/Kunden/NKK/VPN/nkk-secure-access

# Build the app
~/.cargo/bin/cargo tauri build --bundles dmg

# Output:
# src-tauri/target/release/bundle/dmg/NKK Secure Access_X.Y.Z_aarch64.dmg
```

Note: macOS builds are unsigned (no Apple Developer cert yet).
Users must run `xattr -cr "/Applications/NKK Secure Access.app"` after install,
or right-click > Open to bypass Gatekeeper.

### Windows (GitHub Actions CI)
Triggered automatically on push to `main` or when a tag `v*.*.*` is pushed.
Repo: `https://github.com/leonkro-test/nkk-secure-access-test`
Workflow: `.github/workflows/build-windows.yml`

```bash
# Tag and push to trigger release build
git tag v0.3.0
git push origin v0.3.0
```

The CI will:
1. Build the NSIS installer (.exe)
2. Sign it with `TAURI_SIGNING_PRIVATE_KEY` (GitHub secret)
3. Bake the setup key from `NKK_SETUP_KEY` secret into the installer
4. Generate `latest.json` for the auto updater
5. Create a GitHub Release with installer + latest.json

### Manual Windows ZIP (for email distribution)
If you need a password-protected ZIP instead of the auto-updating installer:
```bash
# On the Mac, after CI produces the .exe:
# Download the artifact from GitHub Actions
# Create ZIP with password
zip -P nkk NKK-Secure-Access.zip "NKK Secure Access_X.Y.Z_x64-setup.exe"
```

## 4. Auto Updater

### How it works
- App checks `latest.json` from the configured endpoint 5 seconds after start
- Endpoint (in `tauri.conf.json`): currently the private test repo, **muss vor dem
  Produktivbetrieb auf den finalen oeffentlichen Release-Host gesetzt werden**
- The build now emits the signed updater artifacts because
  `bundle.createUpdaterArtifacts` is `true` (ohne das gibt es keine `.sig` und der
  Updater bekommt eine leere Signatur)
- If remote version > installed version, a banner appears (now also showing the
  changelog section for the new version, pulled from `latest.json` `notes`)
- User clicks "Jetzt installieren" > download with progress > "Neu starten"
- Signed with Ed25519 (pubkey in `tauri.conf.json`, private key in GitHub secrets)

### latest.json format (auto-generated by CI)
```json
{
  "version": "X.Y.Z",
  "notes": "NKK Secure Access X.Y.Z",
  "pub_date": "2026-04-14T12:00:00Z",
  "platforms": {
    "windows-x86_64": {
      "signature": "<base64 sig content from .sig file>",
      "url": "https://github.com/leonkro-test/nkk-secure-access-test/releases/download/vX.Y.Z/NKK Secure Access_X.Y.Z_x64-setup.exe"
    }
  }
}
```

To add macOS auto-update, add a `"darwin-aarch64"` entry to `platforms` with the `.app.tar.gz` URL and signature.

### GitHub Secrets required
| Secret | Purpose |
|--------|---------|
| `TAURI_SIGNING_PRIVATE_KEY` | Signs the updater build (Ed25519) |
| `NKK_SETUP_KEY` | Baked into installer for auto-enrollment |

## 5. Deploy to Server

### Upload Windows ZIP for download link
```bash
scp NKK-Secure-Access.zip root@192.168.0.50:/opt/nkk-api/downloads/
```

### Upload macOS DMG
```bash
scp "NKK Secure Access_X.Y.Z_aarch64.dmg" root@192.168.0.50:/opt/nkk-api/downloads/
```

### Update API news
SSH into `root@192.168.0.50`, edit `/opt/nkk-api/` news data.

## 6. Git Tag and Commit

```bash
# Stage all version-bumped files
git add src-tauri/tauri.conf.json src-tauri/Cargo.toml src-tauri/resources/branding.json docs/anleitung.html src/screens/NewsScreen.tsx

# Commit
git commit -m "release: vX.Y.Z — <short description>"

# Tag
git tag vX.Y.Z

# Push (triggers Windows CI build + GitHub Release)
git push origin main --tags
```

## 7. Post-Release Checklist

- [ ] Version numbers match in all 4 files
- [ ] NewsScreen.tsx has entry for new version
- [ ] HTML Anleitung version updated
- [ ] Git tagged and pushed
- [ ] GitHub Actions build succeeded
- [ ] GitHub Release created with installer + latest.json
- [ ] Windows ZIP uploaded to server (if distributing via email)
- [ ] macOS DMG uploaded to server (if distributing via email)
- [ ] Test auto-update from previous version (install old, wait for banner)
- [ ] Test fresh install on Windows
- [ ] Test fresh install on macOS (with xattr fix)

## Architecture Notes

- **Updater plugin:** `tauri-plugin-updater` v2.10.1
- **Signing:** Ed25519 via Tauri's built-in minisign
- **Windows installer:** NSIS with custom hooks (`src-tauri/nsis/installer.nsh`)
- **macOS installer:** DMG with branded background (`src-tauri/icons/dmg-background.png`)
- **Bundled NetBird (Windows only):** Fetched by `src-tauri/bin/fetch-netbird.ps1`
- **Bundled VC++ Runtime (Windows only):** `vc_redist.x64.exe` fetched by same script, installed silently if `vcruntime140.dll` missing
- **Bundled wintun.dll (Windows only):** WireGuard tunnel driver, fetched by same script, copied to System32 if missing
- **macOS NetBird:** Installed on first launch via `install_netbird` command (curl | sh)
- **Enrollment API:** `https://api.secure.nkk-hb.de/api/enrollment` receives diagnostic on first connect
- **News API:** `https://api.secure.nkk-hb.de/api/news` serves remote news JSON
